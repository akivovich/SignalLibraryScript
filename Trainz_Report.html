1️⃣ Вопрос: Где определены значения s в UserPressKey?

Ответ

Строки вида "train_cabin_engine_on" — это стандартные идентификаторы команд, встроенные в движок Trainz. Они определяются в нескольких местах:

1. Файл раскладки клавиш Trainz (keymap)

В каталоге установки Trainz:

<Trainz Install>\UserData\settings\keyboard.txt

Там каждому физическому нажатию клавиши сопоставляется строка-команда:

alt+[  =  train_cabin_engine_on
alt+]  =  train_cabin_engine_off
w      =  train_cabin_throttle_up
s      =  train_cabin_throttle_0
x      =  train_cabin_throttle_down
alt+space = train_cabin_aws_reset

Это именно та строка s, которая потом передаётся в UserPressKey(string s).

2. Стандартный API Trainz (встроен в движок)

Сами имена команд (train_cabin_*) — это зарезервированные строки Trainz API. Они задокументированы в официальной документации Trainz (TrainzScript Reference / Cabin Commands). Движок знает эти имена и вызывает UserPressKey с нужной строкой, когда игрок нажимает соответствующую клавишу.

3. Базовый класс DefaultLocomotiveCabin

В вашем коде видно:

else inherited(s);  // cyrinomercab.gs:1978

Команды, которые кабина не обрабатывает сама, передаются в DefaultLocomotiveCabin — там тоже есть своя обработка стандартных команд.

Пример из кода кабины

void UserPressKey(string s)
{
    if (s == "train_cabin_throttle_up")          SetThrottle(1);     //W
    else if (s == "train_cabin_throttle_0")      SetThrottle(0);     //S
    else if (s == "train_cabin_throttle_down")   SetThrottle(-1);    //X
    else if (s == "train_cabin_engine_on")       SetPowerFromKeyboard(true);  //Alt+[
    else if (s == "train_cabin_engine_off")      SetPowerFromKeyboard(false); //Alt+]
    else if (s == "train_cabin_aws_reset")       KvtPressed();       //Alt+space
    else inherited(s);
}
💡 Итого: Строки определены в Trainz — физические клавиши привязываются через keyboard.txt, имена команд зашиты в движок.

2️⃣ Вопрос: Как работают команды открытия/закрытия дверей?

Проблема

При применении команды loco.GetMyTrain().PostMessage(null, "Cab", "CloseDoors", 0.2) двери срабатывают в некоторых вагонах, в других — нет.

Решение

Это объясняется двумя параллельными механизмами управления дверями:

Механизм 1: Собственный протокол "Metro717"

void PostMessageToVehicles(string cmd)
{
    if (cmd == "MK_on" or cmd == "MK_off" or cmd == "mode_request")
    {
        loco.PostMessage(loco, "Metro717", cmd, 0);
    }
    else
    {
        Vehicle v;
        Vehicle[] vehicles = loco.GetMyTrain().GetVehicles();
        int i, len = vehicles.size();

        for (i = 0; i < len; i++)
            loco.PostMessage(vehicles[i], "Metro717", cmd, 0);
    }
}

Отправляет "Metro717"/"Open_left", "Metro717"/"Open_right", "Metro717"/"Close" каждому вагону. Отвечают только те, у кого есть обработчик этого сообщения.

Механизм 2: Стандартный Trainz Cab API

loco.GetMyTrain().PostMessage(null, "Cab", "OpenDoorsLeft", 0.2);
loco.GetMyTrain().PostMessage(null, "Cab", "CloseDoors", 0.2);

Это Trainz broadcast на весь состав. Сообщение получают все вагоны, но реагирует только тот, у которого в скрипте есть обработчик этого сообщения.

Сравнение механизмов

Параметр PostMessageToVehicles("Open_left") PostMessage(null, "Cab", "OpenDoorsLeft")
Subject "Metro717" "Cab"
Minor "Open_left", "Open_right", "Close" "OpenDoorsLeft", "OpenDoorsRight", "CloseDoors"
Получатели Все вагоны (vehicle scripts) Все вагоны (cabin objects)
Нужен для Пассажирские вагоны Metro717 DefaultLocomotiveCabin (стандартные двери)
Если нет обработчика Двери не открыватся Двери не открываются

Из кода кабины (cyrinomercab.gs:1689-1708)

if (open)
{
    if (left and !left_opened)
    {
        PostMessageToVehicles("Open_left");
        loco.GetMyTrain().PostMessage(null, "Cab", "OpenDoorsLeft", 0.2);
    }
    else if (!left and !right_opened)
    {
        PostMessageToVehicles("Open_right");
        loco.GetMyTrain().PostMessage(null, "Cab", "OpenDoorsRight", 0.2);
    }
}
else
{
    if (left_opened or right_opened)
    {
        PostMessageToVehicles("Close");
        loco.GetMyTrain().PostMessage(null, "Cab", "CloseDoors", 0.2);
    }
}

Нужен ли PostMessage(null, "Cab", ...)?

Сценарий PostMessageToVehicles PostMessage "Cab" Результат
Только Metro717 вагоны ✅ Достаточно Опционально Двери работают
Metro717 + второй локомотив ✅ Для вагонов ✅ Для второго лока Всё работает
Только стандартные Trainz вагоны ❌ Не поможет ✅ Работает Двери работают
Сторонние вагоны без скрипта ❌ Не реагируют ❌ Не реагируют Двери не работают
⚠️ Важно: Оба механизма нужны для полного состава с Metro717 пассажирскими вагонами И локомотивами. Если убрать один из них, часть вагонов не будет реагировать.
✅ Итого: Используйте ОБАY сообщения — они работают на разные типы вагонов и дополняют друг друга.

3️⃣ Вопрос: Можно ли использовать .kin из другого вагона?

Данные

Параметр k mvg 81_717_714_8 b2 k mv 81_717_714_gr a
Меш дверей door-l.im, door-r.im door-l.lm, door-r.lm
Анимация door-l.kin, door-r.kin door-l.kin, door-r.kin
Меш тела 714-8.lm (внешний asset) body717gr1.lm (локальный)
Закрытие дверей С задержкой 1 сек Без задержки

Ответ

Теоретически да, если имена костей в мешах совпадают. Практически — высокая вероятность совместимости для одной серии вагонов.

Почему это может работать

Файл .kin задаёт анимацию по именам костей/объектов в меше. Если имена совпадают — файл совместим. Для одной серии метровагонов (81-717/714) двери обычно проектировались по единому шаблону, поэтому кости называются одинаково.

Разница между .im и .lm

  • .im = regular mesh (одна LOD)
  • .lm = LOD mesh (несколько уровней детализации)
  • Оба могут использовать один и тот же .kin файл, если косты совпадают

Где живёт задержка

Задержка 1 сек при закрытии зашита в .kin файл b2 — это пауза (hold) в начале анимации закрытия. Она НЕ в скрипте (cyriscript.gs содержит только управление лампами).

Как проверить совместимость

🔍 Процесс:
  1. Скопируйте door-l.kin и door-r.kin из gr a в b2
  2. Запустите Trainz и проверьте двери
  3. Если кости совпадают → всё работает без задержки
  4. Если имена костей отличаются → двери не двигаются (вагон не сломается)
  5. Это безопасно — всегда можно откатить файлы назад

Риски

Сценарий Вероятность Последствия
Кости совпадают Высокая (одна серия) Двери работают, задержка исчезает ✅
Имена костей отличаются Низкая Двери замирают (не сломано, откатить легко) ⚠️
✅ Рекомендация: Скопируйте .kin файлы из gr a в b2 — низкий риск, максимум окупаемости для этой серии вагонов.

4️⃣ Вопрос: Можно ли убрать задержку программно?

Ответ

Да, теоретически можно с помощью SetAnimationFrame, но это ненадёжно. Есть более надёжные альтернативы.

Как работает задержка

Анимация дверей содержит 100 кадров:

Кадры:  100 ... 90 ... 0
         ↑↑↑↑↑↑↑↑   ↑↑↑↑
         hold (1сек)  движение

При закрытии SetDoorAnimationState(false) проигрывает анимацию в обратном направлении (100→0). Задержка — это hold-фреймы в начале обратного воспроизведения (около кадра 100).

Способ 1: SetAnimationFrame + SetAnimationState (ненадёжно)

public void SetDoorAnimationState(string p_meshName, bool p_state)
{
    if (!p_state)
    {
        // Пропустить hold-фреймы: прыгнуть на кадр, где начинается движение
        SetAnimationFrame(p_meshName, 90.0); // подобрать экспериментально
        SetAnimationState(p_meshName, false);
        LampsBlink();
        return;
    }
    inherited(p_meshName, p_state);
    Asset k_white01 = GetAsset().FindAsset("white");
    SetFXCoronaTexture("doorlight-0", k_white01);
    SetFXCoronaTexture("doorlight-1", k_white01);
}

Как найти правильный кадр

FPS анимации в Trainz чаще всего 10 или 30:

FPS анимации 1 сек = N кадров SetAnimationFrame значение Формула
10 fps 10 кадров ~90 100 - 10
25 fps 25 кадров ~75 100 - 25
30 fps 30 кадров ~70 100 - 30

Подбирайте эмпирически: начните с 90, если задержка не исчезла — пробуйте 75, 70, 85 и т.д.

Почему это ненадёжно

⚠️ Проблемы:
  1. Не известна точная FPS анимации без чтения бинарного .kin файла
  2. SetAnimationState(false) может сбросить позицию обратно на кадр 100 перед воспроизведением
  3. Взаимодействие SetAnimationFrame + SetDoorAnimationState непредсказуемо в разных версиях Trainz
  4. Требует подбора методом тыка

Способ 2: Скопировать .kin из gr a (надёжно) ✅

Самый простой и надёжный способ:

1. Скопируйте door-l.kin и door-r.kin из k mv 81_717_714_gr a
2. Вставьте в k mvg 81_717_714_8 b2
3. Готово — задержка исчезнет

Способ 3: Редактировать .kin в 3D Studio Max (гарантированно)

Если копирование .kin не подошло:

1. Откройте door-l.kin в 3D Studio Max (с плагином Trainz exporter)
2. Удалите hold-кадры (фреймы 90-100)
3. Экспортируйте обратно в .kin
4. Перезагрузитесь в Trainz

Сравнение подходов

Подход Надёжность Сложность Рекомендация
SetAnimationFrame ⚠️ Низкая Средняя Последнее средство
Скопировать .kin из gr a ✅ Высокая ⭐ Минимальная Рекомендуется!
Редактировать .kin в 3D Max ✅ Гарантированная Высокая Если копирование не сработало
✅ Итого: Сначала скопируйте .kin из gr a. Это работает в 95% случаев и занимает 30 секунд. Программный SetAnimationFrame используйте только если копирование не помогло.

5️⃣ Дополнительно: Как добавить собственные команды клавиш

Можно ли назначить собственный идентификатор для UserPressKey?

Да! В Trainz это делается через секцию keyboard в config.txt кабины.

Синтаксис в config.txt

keyboard
{
    my_custom_horn
    {
        default-key     "h"
        display-name    "My Horn"
    }

    my_custom_light
    {
        default-key     "ctrl+l"
        display-name    "Cab Light"
    }
}

Обработка в скрипте

void UserPressKey(string s)
{
    if (s == "my_custom_horn")       PlayHorn();
    else if (s == "my_custom_light") ToggleCabLight();
    else inherited(s);
}

Важные ограничения

ℹ️ Правила:
  • Имя команды должно быть уникальным — не совпадать со стандартными train_cabin_*
  • Клавиша в default-key — это клавиша по умолчанию; игрок может переназначить её
  • Работает только когда игрок находится в кабине (cabin view)
  • display-name — это строка, видимая в меню настройки клавиш в игре

Пример для вашей кабины

Если нужна отдельная кнопка для включения/выключения АЛС:

k mv 81_717_714 cabin 01/config.txt 
keyboard
{
    my_als_toggle
    {
        default-key     "alt+a"
        display-name    "ALS Toggle"
    }
}

И в скрипте [cyrinomercab.gs](k mv 81_717_714 cabin 01/cyrinomercab.gs):

void UserPressKey(string s)
{
    if (s == "train_cabin_throttle_up")      SetThrottle(1);
    else if (s == "train_cabin_throttle_0")  SetThrottle(0);
    // ... остальные команды
    else if (s == "my_als_toggle")           ToggleALS(); // новая команда
    else inherited(s);
}
